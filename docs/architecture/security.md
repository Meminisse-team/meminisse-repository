# Private media and browser authentication

S3 must be private: enable all four Block Public Access settings, disable ACLs (Bucket owner enforced), remove public bucket policies, and grant the service role only the needed object operations. Application code cannot revoke an existing public bucket policy; verify these settings before deployment.

Migration 017 removes stored media URLs and replaces manuscript URLs with keys. Historical generated PDFs use `users/{user_id}/manuscripts/{id}.pdf`; confirm object existence and back up the database before migration. Ownership checks precede issuance of 5-minute presigned GET URLs. URLs are bearer capabilities: do not log or persist them. API field names remain `s3_url` and `pdf_url` for compatibility, but values expire. Refetch the resource when needed. PDF buttons request a fresh owner-authorized capability at click time. New PDFs have unique version keys so polling can distinguish regeneration from signed-URL rotation; apply a private-bucket retention policy for superseded objects. PDF rendering signs image access while rendering.

Uploads accept JPEG/PNG/WebP up to 10 MiB and 25 million pixels. The server checks declared MIME against decoded format, verifies and decodes the image, reads in bounded chunks, and uses UUID object names. Set an ingress body limit of 11 MiB including multipart overhead too: application checks occur after multipart parsing. Image originals may contain EXIF; access remains private.

The browser calls a same-origin Next.js BFF. Access and refresh tokens are HttpOnly, SameSite=Strict cookies, Secure in production. Use HTTPS and set server-only `API_BASE_URL` to FastAPI. Set `APP_ORIGIN` to the exact public origin (scheme, hostname, optional port; no trailing slash) behind a reverse proxy. Without this setting, the BFF compares Origin to the request Host and protocol; it never trusts an arbitrary X-Forwarded-Host. Mutations require an exact Origin match. Only the BFF forwards bearer tokens; login response bodies never return tokens to JavaScript. A single-flight refresh per browser tab retries each failed request at most once. Logout clears cookies; provider-wide revocation is not implied. Legacy localStorage tokens are removed and signup drafts are memory-only (reloading restarts signup). HttpOnly does not prevent XSS from issuing same-origin requests; escaping and deployment CSP remain necessary.

Provider failures return a generic 502. Structured server logs record status and request identifier without response bodies or customer content.
